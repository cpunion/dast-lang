# 热更新 (Hot Reload) 架构

## 设计目标

1. **模块级热更新**: 运行时替换模块代码，无需重启
2. **多版本共存**: 允许同一模块的多个版本同时运行
3. **零成本可选**: 不使用热更新时无额外开销
4. **双模式执行**: 支持字节码 (灵活) 与机器码 (性能)

---

## 架构选型: 方案 B + C 混合

### 主体架构: 函数指针表 + 多版本

```
┌─────────────────────────────────────────────────────────────┐
│                    Hot Reload 核心架构                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │                    主程序 (Host)                       │  │
│  │  ┌─────────────────────────────────────────────────┐  │  │
│  │  │          模块函数表 (间接调用层)                  │  │  │
│  │  │   ┌──────────┬──────────┬──────────┬─────────┐  │  │  │
│  │  │   │ module_a │ module_b │ module_c │ ...     │  │  │  │
│  │  │   │ v2 ●     │ v1 ●     │ v3 ●     │         │  │  │  │
│  │  │   └────┬─────┴────┬─────┴────┬─────┴─────────┘  │  │  │
│  │  └────────┼──────────┼──────────┼──────────────────┘  │  │
│  └───────────┼──────────┼──────────┼─────────────────────┘  │
│              │          │          │                        │
│              ▼          ▼          ▼                        │
│  ┌───────────────┐ ┌───────────┐ ┌───────────────┐         │
│  │ module_a v2   │ │module_b v1│ │ module_c v3   │         │
│  │ (native code) │ │(bytecode) │ │ (native code) │         │
│  └───────────────┘ └───────────┘ └───────────────┘         │
│              │                                              │
│  ┌───────────────┐  ← 旧版本可保留 (正在被调用的模块)        │
│  │ module_a v1   │                                          │
│  │ (卸载中/GC)   │                                          │
│  └───────────────┘                                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 多版本共存机制

```
┌─────────────────────────────────────────────────────────────┐
│                   多版本生命周期管理                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  时间线:                                                    │
│  ────────────────────────────────────────────────────────▶  │
│                                                             │
│  T0: module_a v1 加载，激活                                 │
│      ┌───────────────┐                                      │
│      │ v1 [ACTIVE]   │                                      │
│      └───────────────┘                                      │
│                                                             │
│  T1: v2 编译完成，函数表指向 v2                              │
│      ┌───────────────┐ ┌───────────────┐                    │
│      │ v1 [DRAINING] │ │ v2 [ACTIVE]   │                    │
│      └───────────────┘ └───────────────┘                    │
│      ↑ 正在执行的调用继续使用 v1                             │
│        新调用进入 v2                                        │
│                                                             │
│  T2: v1 所有调用完成，可卸载                                 │
│                        ┌───────────────┐                    │
│      (v1 unloaded)     │ v2 [ACTIVE]   │                    │
│                        └───────────────┘                    │
│                                                             │
│  特殊: 库的多版本依赖                                        │
│   ┌──────────┐        ┌──────────┐                          │
│   │ app_mod  │───────▶│ lib v1.0 │                          │
│   └──────────┘        └──────────┘                          │
│   ┌──────────┐        ┌──────────┐                          │
│   │ plugin_a │───────▶│ lib v2.0 │  ← 允许共存               │
│   └──────────┘        └──────────┘                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 模式选择策略

| 场景 | 推荐模式 | 理由 |
|------|---------|------|
| 开发迭代 | 字节码 | 编译快、热更无缝 |
| 生产部署 | 机器码 | 性能最优 |
| 边缘设备 | 机器码 | 无解释器开销 |
| 嵌入式热更 | 字节码 | 灵活替换 |
| 插件系统 | 字节码 | 隔离安全 |

## 状态管理

### 热更时的状态处理

```
┌─────────────────────────────────────────────────────────────┐
│                    状态迁移策略                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  策略 1: 显式钩子函数                                        │
│  ┌─────────────────────────────────────────────┐            │
│  │ @hot_reload                                 │            │
│  │ module GameLogic {                          │            │
│  │     var state: GameState                    │            │
│  │                                             │            │
│  │     // 卸载前: 导出状态                     │            │
│  │     fn __on_unload__() -> []u8 {            │            │
│  │         return serialize(state)             │            │
│  │     }                                       │            │
│  │                                             │            │
│  │     // 加载后: 导入状态                     │            │
│  │     fn __on_load__(data: ?[]u8) {           │            │
│  │         if data {                           │            │
│  │             state = deserialize(data)       │            │
│  │         } else {                            │            │
│  │             state = GameState.default()     │            │
│  │         }                                   │            │
│  │     }                                       │            │
│  │ }                                           │            │
│  └─────────────────────────────────────────────┘            │
│                                                             │
│  策略 2: 共享内存 + ABI 稳定                                 │
│  ┌─────────────────────────────────────────────┐            │
│  │ // 状态定义在独立的共享区，布局固定          │            │
│  │ @shared @abi_stable(1)                      │            │
│  │ struct GameState {                          │            │
│  │     score: i32,                             │            │
│  │     level: i32,                             │            │
│  │     // 新版本可追加字段，但不能修改已有字段   │            │
│  │ }                                           │            │
│  │                                             │            │
│  │ // 状态分配在共享区                          │            │
│  │ @shared                                     │            │
│  │ var state: GameState                        │            │
│  └─────────────────────────────────────────────┘            │
│                                                             │
│  策略 3: 仅无状态函数可热更                                  │
│  ┌─────────────────────────────────────────────┐            │
│  │ @hot_reload                                 │            │
│  │ fn calculate_damage(atk: i32, def: i32) i32 │            │
│  │ // 纯函数，无状态，可自由替换               │            │
│  │                                             │            │
│  │ // 状态保留在 host 侧，不参与热更            │            │
│  └─────────────────────────────────────────────┘            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 编译流程

```bash
# 开发模式: 生成字节码，支持热更
$ dast build --mode=dev --hot-reload

# 生产模式: 生成优化的机器码
$ dast build --mode=release

# 混合模式: 核心模块机器码，插件字节码
$ dast build --mode=hybrid \
    --native=core,render \
    --bytecode=plugins/*
```

## 与无 GC 的兼容

| 问题 | 解决方案 |
|------|---------|
| 旧版本模块的内存 | 引用计数追踪模块使用 (仅模块级，非对象级) |
| 函数指针悬垂 | 函数表间接调用，指针始终有效 |
| 结构布局变更 | 序列化/反序列化迁移 或 禁止 (ABI 稳定) |
